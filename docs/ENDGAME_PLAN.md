## 7. P4 — risk model (pinned target; cut before any of P0–P3)

**Policy (pinned by the user):** risk above threshold τ for k consecutive steps marks a satellite SUSPECT (a `SUSPECT_ALERT` log event); at the next placement decision, critical roles prefer the lowest-risk satellites. Assignment stays Hungarian. The model never predicts assignments.

**Value-of-warning sweep — runs BEFORE any model (added 2026-09-29 after user review):** the generator writes the precursors, so a positive headline delta is near-guaranteed and proves little ("you decided failures give warning, then showed you use it"). The honest deliverable is the **value-of-warning curve**: coverage retained and Δv spent versus warning lead time L ∈ {0, 30, 60, 300, 1800} s, using an ORACLE trigger that knows each t_f exactly. It answers a real question — how much lead time is worth having, and what false-alarm rate breaks even. The model's job then shrinks to landing an operating point (lead, false-alarm rate) on that curve; if the model fails, the curve still ships. This also subsumes the Q6 scope ack: the curve is measured on predictor-family scenarios by construction, and the oracle makes the "second delta" question well-posed. Needs the same gated in-loop hook as the predictor path. **Grid fix (2026-09-29 review):** failures fire at t = 1200/1500 s, so L = 1800 s lands before the first failure exists, and even L = 300 s can trigger while the formation is still settling. Each L is therefore capped per failure at `t_f − t_settle`, with t_settle measured from the committed nominal log (first tick where coverage enters its nominal band); grid points above the cap are dropped and the report lists the cap. If a longer-lead point is wanted, the sweep scenario shifts t_f later — labeled NOT comparable to the G4 numbers.

**P4's metric, pinned (2026-09-29 review):** coverage cannot show the predictor's value — killing leader+downlink leaves coverage unchanged (only imagers count, §3.1), and with 4 s reactive detection the benefit is seconds of role outage. The number P4 must move is the **critical-seat health fraction**: the fraction of sim time in which the leader and downlink seats are held by a status-NOMINAL satellite (computed post-hoc from any log — no core diff). If P4 cannot move that fraction beyond the reactive baseline at matched false alarms, P4 is reported as a demo, not a result — and the README says which of the two it is.

**P4 training design adopted (2026-09-29, user review):** (1) the ORACLE value-of-warning sweep runs before any model exists and is the cheapest kill switch — if the oracle shows ~zero gain at every admissible lead time, the model is cut untrained. (2) ADD a **full-mode holdout** to the anti-circularity stack: train WITHOUT one fault family and evaluate on it — hold out the **gradual/EPS-fade** mode, because "the model learned the generator's slope" bites hardest there; passing on held-out gradual is the headline generalization defense. This is IN ADDITION to the shifted-parameter + disjoint-seed train/test split (which stays — a split is still needed at all), not a replacement. (3) Channels stay the sim-grounded set (bus voltage/SoC, thrust duty, heartbeat latency/jitter, temperature) — **NO wheel-current or SNR channels**: the sim has neither, and invented hardware feeds the circularity criticism. (4) Labels come from the sim's own deterministic failure schedule — no separate label pipeline, no leakage across the heartbeat boundary. (5) False-alarm cost stays pinned: every false alarm is a full unnecessary reassignment at the ~194 m/s scale; report FA rate AND Δv per false alarm; the Δv-per-false-alarm ≤ 10 % of measured recovery Δv gate stands. (6) Count honesty stands: ~≤ 30 test events — raw counts + exact intervals, no dressed-up percentages.

**Generator — `cubesat/telemetry.py` (new file; sim core untouched):**
- Telemetry is a pure deterministic function of the existing pipeline: it consumes byte-identical JSONL logs (the golden-hash evidence, GATES.md:8–9) for ground truth (per-tick positions, `dv_used`, status, failure schedule) and synthesizes bus channels around it. One sample per tick, dt = 2 s; one orbit = 5677 s ≈ 2838.5 ticks at 500 km.
- Channels: `bus_voltage_v` (7.4 V nominal, AR(1) noise σ ≈ 0.02 V, deterministic eclipse dip keyed to orbit phase), `soc_frac` (integrator: discharge in eclipse, solar charge otherwise), `thrust_duty` (0 nominal; nonzero only during real PD burns — cross-checked against `dv_used` deltas in the log, which are real, not synthetic), `hb_latency_ms` (40 ms + AR(1) σ = 5 ms), `hb_jitter_ms` (rolling std), `temp_c` (20 °C + orbit-phase sine + noise).
- Three failure families, one per scheduled failure entry: (1) **EPS fade** — ramp R ∈ [1800, 3600] s ending at t_f; voltage drains ~0.03–0.05 V/min, SoC falls faster than the eclipse profile explains, temp drifts +3–6 °C; precursor visible ≥ 10 min early. (2) **Comms degradation** — latency mean 40→120 ms, jitter σ 5→40 ms over R; ends in silence; the jitter channel discriminates. (3) **Sudden death** — no overlay; recall ≈ 0 by construction; the reactive path (4 s detection) is the safety net, and the README says so (§11).
- **Anti-circularity:** every generator parameter (R, drift rates, noise σ, distractors) is drawn per-run from `numpy.random.Generator(PCG64)` seeded via `SeedSequence(scenario.seed).spawn()` per (satellite, channel) — the repo's FIRST RNG consumer (recon: zero RNG today; the seed is otherwise a pure label). Train family: seed range A. Test family: disjoint seed range B AND shifted parameters (R ∈ [3600, 5400] s, different drift magnitudes, compound modes like EPS fade + elevated jitter). Benign distractors (self-recovering voltage excursions, eclipse transients, burn pulses) as false-alarm bait. Scale: ~90 runs × 3–6 sats × 8515 ticks; predictor-family scenarios under `data/scenarios_predictor/*.json` with their own new golden pins — existing pins untouched (user constraint).

**Features — `cubesat/telemetry_features.py`:** strictly past-only: at tick t every feature uses samples ≤ t (one-tick shift where a window endpoint could touch t). Windows tied to dt = 2 s: W ∈ {15, 60, 300} ticks. Per channel/window: last, mean, std, trend (mean of latest W/2 − mean of previous W/2), min, max; cross-window contrast mean_15 − mean_300; robust z vs median and 1.4826·MAD with the **SAME** baseline rule (expanding per-sat history) at train and serve — the train/serve skew risk is killed by construction (risk #2). Comms-specific: near-miss beat counts, rolling latency std at W = 60/300, max latency, ticks-since-spike. Power-specific: eclipse-detrended voltage residual, SoC slope at W = 300. Labels: y(t) = 1 iff t ∈ [t_f − L, t_f) with lead horizon L = 150 ticks = 300 s; post-onset censored; warmup ticks (t < 300) dropped so every window exists — no NaN plumbing. Class balance ≈ **0.6–1.2% positives** per run — 2 slow-family failures × L = 150 ticks = 300 positive (sat, tick) samples vs 3–6 sats × 8515 ticks ≈ 25.5k–51k samples (300/51090 ≈ 0.6% at 6 sats, 300/25545 ≈ 1.2% at 3 sats; lower still when a run's failures are sudden-death and contribute zero positives) → PR-focused choices throughout.

**Baseline — `cubesat/baseline_detectors.py` (~80 lines, zero new dependencies; the honest fallback):** per (satellite, channel), robust μ, s (median, 1.4826·MAD) from the first-orbit nominal window; **EWMA** (NIST/SEMATECH §3.2.4): z_t = λ·y_t + (1−λ)·z_{t−1}, σ_ewma = s·√(λ/(2−λ)) (√(0.1/1.9) = 0.2294), alarm on leaving μ ± k·σ_ewma, λ ∈ {0.1, 0.2} swept — primary for EPS fade; **CUSUM** (NIST §3.2.3): S_hi = max(0, S_prev + y − μ − k) mirrored low, k = 0.5σ, h ≈ 4–5σ — primary for the comms mode via the rolling-std-of-latency series. Calibration: sweep (k, h, λ) on train+validation NOMINAL segments; threshold = empirical quantile of the max-statistic achieving ~0.5 alarm events/sat-orbit.
