**A-4 | P1 | Replay seek produces frames that differ from linear playback (stale `assignment_map` and `detection_latency_s` in the server-side enrich)**
- Where: `cubesat/session.py:363-378` (`seek` moves the cursor but never rebuilds `self.enrich`), `cubesat/wire.py:221-226, 207-218` (enrich is mutated as events stream past).
- Repro (verified, `/tmp/seek_test.py`): play `two_failure.jsonl` to the end, then `seek(0.0)`:
  ```
  after seek 0: first frame t 0.0 n sats 0          # INIT replayed
  real frame t 0.0 [('SAT-1','slot_1'), ('SAT-2',None), ('SAT-3','slot_0'), ('SAT-4','slot_2'), ('SAT-5','slot_0'), ...]
  metrics {'detection_latency_s': 4.0, ...}          # t=0, before any failure
  ```
  Forward seek (`/tmp/seek3.py`): fresh load, seek to 9000 s: `SAT-1 healthy None, SAT-2 failed None, ... ` every `target_slot` is None, `detection_latency_s` None, even though the run is RECOVERED with a re-phased 4-seat formation.

**A-15 | P2 | Landing scene leaks post-processing GPU resources on every route change; neither renderer calls `forceContextLoss`**
- Where: `landing/landingScene.ts:426-430` creates `EffectComposer` + `RenderPass` + `UnrealBloomPass` + `OutputPass`; `dispose()` at `:640-672` calls `composer.dispose()` and `renderer.dispose()` only.

**A-16 | P2 | After a backend restart the UI keeps `mode: "live"` and an enabled Inject button; no event or reassignment backfill on reconnect**
- Where: `stores/simStore.ts:97-102` (`mode: msg.mode === "stopped" ? state.mode : msg.mode`); `useWebSocket.ts` reconnect path; `session.py hello()/snapshot()` carry no history.
- Reasoning (read-only): a restarted server sends `hello{mode:"stopped"}` plus an INIT snapshot. The INIT frame clears satellites (`simStore.ts:110`), but `mode` stays `live`/`replay`, so `FailureInjectionPanel` (`mode === "live"`) offers injection that returns 409 "failure injection requires a live run". After a transient disconnect mid-run, events and `role_reassignment` messages emitted during the gap are never replayed, so Recovery Log and the reallocation table can miss an ASSIGNMENT. Also `simStore.ts:147` flips `stopped` to `live` on any frame, so a frame queued before a Reset can resurrect `live` (unverified race).
- Fix: honour `hello.mode === "stopped"`; on reconnect, request or receive a recent-events backfill.
- Track: L1 / L3.
